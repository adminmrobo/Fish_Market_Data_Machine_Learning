Before changing the model: four ways to improve performance

When a classification model falls short of expectations, there is a lot you can do before changing the model. This guide covers ways to improve performance while keeping the model as it is: fix the evaluation so you can trust the score (1), tune the training process that finds the weights (2), create features while regularizing against overfitting (3), and finally combine several models (4).

Fixing errors in the data splitStratify · Cross-validation

First, tell whether the score reflects the model's skill or just the luck of the split.

①What's the problem · with a single split, the score depends on luck

There are 120 points: 102 blue dots (majority class) and 18 orange hollow circles (minority class), so the minority is 15%. We split them into a training set of 84 and a test set of 36, train KNN (k = 5) looking only at the training set, and score it on the test set. The background color is the model's decision. Every time you press "Split again," the accuracy changes even though the data and the model are the same.

Split method

Test accuracy from each split so far

Switching to stratified fixes the minority class in the test set at 5 every time (about 15%, the same as overall). With random splitting it swings between 2 and 9 each time, so sometimes the model is scored having barely seen the minority class.

In plain wordsIf you pick a class representative with an exam using just one question sheet, a student who happened to get easy questions might be chosen. Taking the exam several times with different sheets and averaging filters out luck. That is cross-validation. Stratified sampling (stratify) is like a poll that draws its sample so the age-group proportions match the population exactly.

②Principles and formulas
ntest, k ≈ ntest × (nk / n)Stratified sampling: the number of class k in the test set is matched to its overall proportion.
CV = (1/K) Σk=1K sk,   report also: standard deviation σK-fold cross-validation: average the K scores sk, and report the spread (σ) as well.
Precision = TP / (TP + FP),   Recall = TP / (TP + FN),   F1 = 2PR / (P + R)With imbalanced data, look at these metrics alongside accuracy. What the four cells TP, FN, FP and TN are, and how real numbers fill them, is shown in the confusion matrix in ④.
The roles of the three datasets
  1. Training setThe data used to learn the weights. It's the textbook.
  2. Validation (cross-validation)The data used to choose and compare hyperparameters. It's the practice exam. Often it isn't set aside separately but replaced by cross-validation.
  3. Test setThe data you look at only once, at the very end, after all choices are made. It's the final exam. If you look at it many times while choosing, you overfit to the test set.
③Cross-validation · every point takes the test once

It's the same 120 points and the same model (KNN, k = 5) as in ①. This time the points are split into five pieces with matching class proportions (stratified), and each piece takes a turn as the test set. In each figure, the dark points are that round's test piece and the faint points are for training. The average of the five scores is the cross-validation score.

Which fluctuates less: the single-split score from ① or the cross-validation average?

The more you split in ①, the more dots pile up in the top row. Check that the bottom row (cross-validation averages) clusters much more tightly. That's why you should report the cross-validation average instead of a single-split score.

④What to check as well · Leakage and the confusion matrix
Data leakage: the mistake of peeking at the answer sheet before the test
  • Scaling or filling missing values before splitting: the mean of the test data gets mixed into training. Put preprocessing inside a Pipeline so it is computed only on the training folds.
  • Duplicate data: if the same person or the same document ends up in both training and test, the model gets it right with a memorized answer. To split by person, use GroupKFold.
  • Ignoring time order: this amounts to predicting the past with future data. For time series, use TimeSeriesSplit to keep the past→future order.

The same thing happens with real data. In the results of the ⑤ code below, plain logistic regression has an accuracy of 0.917, but its recall on the minority class is only 0.357. Giving the minority class more weight with class_weight="balanced" raises recall to 0.700 and lowers accuracy to 0.823. What to prioritize (not missing cases vs. reducing false alarms) depends on the problem.

⑤Code and actual results
# 1. Splitting data: stratify and cross-validation
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

# Imbalanced data with a 10% minority class
X, y = make_classification(n_samples=300, n_features=6, n_informative=4,
                           weights=[0.9, 0.1], random_state=0)

# (1) 20 splits without stratify vs 20 splits with stratify: minority-class share in the test set
plain, strat = [], []
for seed in range(20):
    _, _, _, y_te = train_test_split(X, y, test_size=0.2, random_state=seed)
    plain.append(y_te.mean())
    _, _, _, y_te = train_test_split(X, y, test_size=0.2, random_state=seed, stratify=y)
    strat.append(y_te.mean())
print(f"Overall minority share {y.mean():.3f}")
print(f"Without stratify: test minority share {min(plain):.3f} ~ {max(plain):.3f}")
print(f"With stratify: test minority share {min(strat):.3f} ~ {max(strat):.3f}")

# (2) A single-split score swings with the luck of the split
model = make_pipeline(StandardScaler(), LogisticRegression())   # scaling inside the pipeline: prevents leakage
single = []
for seed in range(20):
    X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=seed, stratify=y)
    single.append(model.fit(X_tr, y_tr).score(X_te, y_te))
print(f"Single-split accuracy, 20 runs: {min(single):.3f} ~ {max(single):.3f}")

# (3) Stratified 5-fold cross-validation: report mean and standard deviation
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
acc = cross_val_score(model, X, y, cv=cv, scoring="accuracy")
rec = cross_val_score(model, X, y, cv=cv, scoring="recall")
print(f"5-fold accuracy {acc.mean():.3f} ± {acc.std():.3f}")
print(f"5-fold recall (minority class) {rec.mean():.3f} ± {rec.std():.3f}")

# (4) The accuracy trap: a model that answers majority class for everything
print(f"Guessing majority class for all: accuracy {1 - y.mean():.3f}, recall 0.000")

# (5) Correcting imbalance: a larger weight for the minority class
balanced = make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced"))
rec_b = cross_val_score(balanced, X, y, cv=cv, scoring="recall")
acc_b = cross_val_score(balanced, X, y, cv=cv, scoring="accuracy")
print(f"class_weight='balanced': recall {rec_b.mean():.3f}, accuracy {acc_b.mean():.3f}")

🐟Seen with fish · Copies of the same fish inflate the score

These 1,554 fish were augmented from the 159 original fish in Kaggle's Fish Market data, taking the normal distribution into account, so there are 9–10 fish that came from each original (same seed_id). If you shuffle and split by individual fish, the training set already contains a near-identical "twin" of each fish in the test set.

How to read it. KNN (k = 1), which copies the single nearest fish, is fooled most by leakage (0.959 → 0.920) — after all, its twin is right next to it. StratifiedGroupKFold, which splits by fish, gives the honest score for "fish it has never seen." The originals-only score is lower not because of leakage, but because there are only 158 rows, so there is little material to learn from.

Stratify too. Whitefish has 48 rows but only 6 fish. If you split into 5 folds by fish, some folds may have no whitefish at all. StratifiedGroupKFold keeps each fish's copies together while balancing the species proportions as evenly as possible.

Show code (fish data, scikit-learn)
import pandas as pd, numpy as np, warnings; warnings.filterwarnings("ignore")
# Load and clean the data: drop rows with weight 0 and exact duplicate rows
df = pd.read_csv("fish_market_x10.csv")
df = df[df["weight_g"] > 0].drop_duplicates().reset_index(drop=True)
FEATS = ["weight_g", "length1_cm", "length2_cm", "length3_cm", "height_cm", "width_cm"]
X, y, groups = df[FEATS], df["species"], df["seed_id"]   # seed_id: group of copies made from the same fish

# Chapter 1 · Leakage with fish data: what if copies of the same fish are split between training and test?
from sklearn.model_selection import StratifiedKFold, StratifiedGroupKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier

print(df.groupby("species").agg(rows=("seed_id", "size"), fish=("seed_id", "nunique")).sort_values("rows", ascending=False).T)

models = {"KNN (k=1)": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=1)),
          "Logistic reg.": make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)),
          "Decision tree": DecisionTreeClassifier(random_state=0)}
plain = StratifiedKFold(5, shuffle=True, random_state=0)          # shuffle and split by row (leakage)
grouped = StratifiedGroupKFold(5, shuffle=True, random_state=0)   # the same seed_id stays on one side only
orig = df[df["source"] == "original"]
print(f"\n{'Model':<10}{'By row':>10}{'By fish':>12}{'Orig. (158)':>12}")
for name, m in models.items():
    a = cross_val_score(m, X, y, cv=plain).mean()
    b = cross_val_score(m, X, y, cv=grouped, groups=groups).mean()
    c = cross_val_score(m, orig[FEATS], orig["species"], cv=StratifiedKFold(5, shuffle=True, random_state=0)).mean()
    print(f"{name:<10}{a:>10.3f}{b:>12.3f}{c:>12.3f}")

Tuning the training processGradient descent · Learning rate · Epoch · Batch

Adjust the step size and the method used to find the weights.

①What's the problem?

Even with the same model, performance suffers if the way it searches for the weights is poor. The loss may not go down, may go down and then jump, or may go down far too slowly.

0.500 → 0.943 → 0.500Test accuracy of the same neural network with only the learning rate changed: 0.0001 → 0.5 → 20
700 vs 1Number of weight updates in one epoch over 700 data points, with batch size 1 vs batch size 700
26 epochsWhere early stopping halted (out of max 500 epochs), test accuracy 0.940

Applies to · This chapter covers models that find their weights with gradient descent: logistic regression, perceptron, linear SVM (SGD), and neural networks. KNN and decision trees don't use gradient descent, so it doesn't apply to them.

Put simplyImagine you are looking for the lowest valley on a mountain covered in thick fog. You can't see far; you can only feel the slope under your feet. Gradient descent means taking one step at a time in the downhill direction. The learning rate is your stride, the batch is the number of people you ask for directions before choosing a direction, and an epoch is one round of asking everyone once.

②Principles and formulas
w ← w − η ∇L(w)One step: move by stride η in the direction opposite to the gradient ∇L.
∇L(w) ≈ (1/B) Σi ∈ batch ∇ℓi(w)Instead of the whole dataset, estimate the direction from the average gradient over a bundle of B samples. The smaller B is, the shakier the estimate.
Updates per epoch = ⌈ n / B ⌉With n data points and batch size B. Example: n = 700, B = 32 gives 22 updates.
Reading the formula piece by piece
  1. ∇L(w)"Nabla L." An arrow that collects how steeply the loss changes for each weight. It points uphill, so we subtract it.
  2. η too smallSafe but slow. It may not reach the bottom within the set number of epochs.
  3. η too largeIt jumps over the valley to the opposite wall, and in bad cases moves farther and farther away and diverges.
  4. ⌈ · ⌉Ceiling symbol. If it doesn't divide evenly, the last small bundle counts as one more.
  5. MomentumLike the inertia of a rolling ball, it carries over part of the previous step's direction. It reduces side-to-side wobbling in narrow valleys and passes flat stretches quickly. In the code below, momentum=0.0 turns it off on purpose to compare pure gradient descent only.
  6. AdamA variant of gradient descent that automatically adjusts the step size for each weight. It shrinks the step in directions that often swing a lot and enlarges it in steady directions. It also uses momentum. Because you need to worry less about the learning rate, it is the default for neural networks (solver="adam").
  7. Scaling and gradient descentIf features have very different units, the loss landscape becomes a valley stretched in one direction, so with a single learning rate one direction is too slow while the other bounces around. Standardization puts the units on the same footing, makes the landscape round, and lets it descend much faster. That's why scaling is practically essential for models that use gradient descent.
③Try it · Changing the learning rate (stride)

The ball moves on the loss curve by w ← w − η × gradient. Try setting η to about 0.01, 0.1, 0.45, and 0.6 and press "Roll automatically." You can also see whether, depending on the starting point, it gets stuck in a small dip (a local minimum).

④Early stopping · When to stop

The training loss (solid line) keeps falling as epochs increase, but the validation loss (dashed line) starts rising again at some point. From then on, instead of learning new rules, the model has started memorizing the training data (overfitting).

Early stopping halts when the validation score hasn't improved for a set number of rounds (n_iter_no_change) and uses the model from the best point. It takes care of the worry "how many epochs should I use?" The figure is an illustrative curve showing the concept.

⑤Code and actual results
# 2. Tuning the training process: learning rate, epochs, batches
import math, warnings; warnings.filterwarnings("ignore")
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.neural_network import MLPClassifier

X, y = make_moons(n_samples=1000, noise=0.25, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
sc = StandardScaler().fit(X_tr); X_tr, X_te = sc.transform(X_tr), sc.transform(X_te)

# momentum=0.0: turn off momentum to compare pure gradient descent only
print("Learning rate comparison (batch 32, 50 epochs, pure SGD)")
for lr in [0.0001, 0.01, 0.5, 20.0]:
    m = MLPClassifier(hidden_layer_sizes=(16, 16), solver="sgd", momentum=0.0,
                      learning_rate_init=lr, batch_size=32, max_iter=50, random_state=0)
    m.fit(X_tr, y_tr)
    print(f"  η = {lr:<7} final loss {m.loss_:.3g}  test accuracy {m.score(X_te, y_te):.3f}")

# Note: this compares the same η and the same epochs, so small batches with more updates have an advantage.
#       In practice, when you increase the batch size, you increase the learning rate too.
print("Batch size comparison (η = 0.01, 50 epochs)")
for bs in [1, 32, len(X_tr)]:
    m = MLPClassifier(hidden_layer_sizes=(16, 16), solver="sgd", momentum=0.0,
                      learning_rate_init=0.01, batch_size=bs, max_iter=50, random_state=0)
    m.fit(X_tr, y_tr)
    print(f"  batch {bs:<4} updates per epoch {math.ceil(len(X_tr) / bs):>3}  loss {m.loss_:.3f}  test {m.score(X_te, y_te):.3f}")

print("Early stopping (stop if the validation score doesn't improve for 10 epochs)")
# solver="adam": adjusts the step size for each weight automatically and also uses momentum
m = MLPClassifier(hidden_layer_sizes=(64, 64), solver="adam", learning_rate_init=0.01,
                  max_iter=500, early_stopping=True, validation_fraction=0.15,
                  n_iter_no_change=10, random_state=0).fit(X_tr, y_tr)
print(f"  stopped at epoch {m.n_iter_}, test accuracy {m.score(X_te, y_te):.3f}")

🐟Seen with fish · Weight in the hundreds, width in single digits: scaling comes before the learning rate

We train a logistic regression that separates perch from roach using 6 features, with gradient descent (SGD). The standard deviation of weight is about 299 g and that of width is 1.6 cm, so their scales differ by nearly 200 times.

Featuresη = 0.0001η = 0.01η = 0.1
Raw unitsLoss 0.635, test 0.576Loss 15.7, test 0.331Loss 13.8, test 0.457
StandardizedLoss 0.606, test 0.689Loss 0.326, test 0.874Loss 0.165, test 0.815

How to read it. In raw units, the gradient in the weight direction is so large that a small learning rate (0.0001) barely moves, and increasing it just a little (0.01) makes the loss jump above 15. It's a stretched valley where no learning rate fits. After standardization, the same learning rate of 0.01 lowers the loss smoothly and reaches a test accuracy of 0.874. This is why you must match the units before choosing a learning rate. η = 0.1 has the lowest training loss, but its test score is actually lower at 0.815, which also shows that you shouldn't choose by loss alone.

Show code (fish data, scikit-learn)
import pandas as pd, numpy as np, warnings; warnings.filterwarnings("ignore")
# Load and clean the data: drop rows with weight 0 and exact duplicate rows
df = pd.read_csv("fish_market_x10.csv")
df = df[df["weight_g"] > 0].drop_duplicates().reset_index(drop=True)
FEATS = ["weight_g", "length1_cm", "length2_cm", "length3_cm", "height_cm", "width_cm"]
X, y, groups = df[FEATS], df["species"], df["seed_id"]   # seed_id: group of copies made from the same fish

# Chapter 2 · Scaling and learning rate with fish data: perch vs roach, 6 features
from sklearn.model_selection import GroupShuffleSplit
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import SGDClassifier
from sklearn.metrics import log_loss

d = df[df["species"].isin(["Perch", "Roach"])]
tr, te = next(GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=0).split(d, groups=d["seed_id"]))
Xtr, Xte = d[FEATS].values[tr], d[FEATS].values[te]
ytr, yte = (d["species"].values[tr] == "Roach"), (d["species"].values[te] == "Roach")
print("Feature scale differences:", {f: round(float(d[f].std()), 1) for f in FEATS})

def run(Xa, Xb, eta, epochs=30):
    m = SGDClassifier(loss="log_loss", learning_rate="constant", eta0=eta, random_state=0)
    losses = []
    for _ in range(epochs):                     # one partial_fit call = 1 epoch
        m.partial_fit(Xa, ytr, classes=[False, True])
        losses.append(log_loss(ytr, m.predict_proba(Xa), labels=[False, True]))
    return losses, m.score(Xb, yte)

sc = StandardScaler().fit(Xtr)
for label, Xa, Xb in [("Raw", Xtr, Xte), ("Scaled", sc.transform(Xtr), sc.transform(Xte))]:
    for eta in [0.0001, 0.01, 0.1]:
        L, acc = run(Xa, Xb, eta)
        print(f"{label:<6} η={eta:<7} loss: epoch 1 {L[0]:7.3f} → epoch 30 {L[-1]:7.3f}   test accuracy {acc:.3f}")

Creating features and taming their side effectsFeature engineering · Overfitting · L2/L1 · Optimization

Add more ingredients, but impose a penalty so the model doesn't memorize. Use a 3D landscape to see minima, maxima, and saddle points.

①What's the problem?

Even a straight-boundary model can draw a curved boundary if you give it new features like x₁² and x₁x₂ (the same idea as kernel SVC raising the dimension to create a curved boundary). But if you create too many features, the model memorizes the training data.

0.830Degree 1 (2 features): test accuracy, boundary too simple
0.910Degree 3 (9 features): test accuracy
1.000 / 0.860Degree 10 (65 features): training / test. Memorized
0.940 / 0.930Degree 10 + L1 regularization (C = 10): training / test, 55 of 65 coefficients are 0

In plain termsFeature engineering is like prepping ingredients before cooking. Julienne a whole potato and a stir-fry becomes possible. But if you expand to dozens of ingredients, the cook ends up like a student memorizing past exam recipes, making dishes that fit only the training data. Regularization is like a luggage weight limit: it charges "an extra fee the heavier your bag," so you pack only what you really need. L2 (ridge) makes every item a little lighter, while L1 (lasso) makes you leave unneeded items out entirely.

②Principles and formulas
(x₁, x₂) → (x₁, x₂, x₁², x₁x₂, x₂², x₁³, …),  number of features = d+2C2 − 1Polynomial features up to degree d. 9 for d = 3, 65 for d = 10.
LL2(w) = L(w) + λ Σj wj²     LL1(w) = L(w) + λ Σj |wj|Add a penalty proportional to the size of the weights to the original loss L. The larger λ, the stronger the regularization.
scikit-learn: C = 1 / λThe C in LogisticRegression is the reciprocal of λ. The smaller C, the stronger the regularization.
Reading the formula piece by piece
  1. λ (lambda)The weight of the penalty. At 0 there is no regularization; if it is too large, all the weights shrink and the model underfits.
  2. Σ wj²The L2 penalty. Larger coefficients are penalized much more (squared), so they all shrink evenly. Near 0 the penalty is almost nothing, so coefficients don't become exactly 0.
  3. Σ |wj|The L1 penalty. Even small coefficients are penalized at the same rate, so useless coefficients become exactly 0. That is why it has a feature selection effect.
  4. Ridge · LassoThese are originally the names of linear regression models with regularization. For classification, it is more accurate to say "L2/L1-regularized logistic regression."

# 3. Feature creation → overfitting → regularization (L2 ridge-type, L1 lasso-type)
import warnings; warnings.filterwarnings("ignore")
import numpy as np
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split, GridSearchCV, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LogisticRegression

X, y = make_moons(n_samples=200, noise=0.3, random_state=1)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, random_state=1, stratify=y)

def poly_logit(degree, penalty=None, C=1.0):
    clf = (LogisticRegression(C=1e6, max_iter=20000) if penalty is None else
           LogisticRegression(penalty=penalty, C=C, solver="liblinear", max_iter=20000))
    return make_pipeline(PolynomialFeatures(degree, include_bias=False), StandardScaler(), clf)

print("Adding features (no regularization)")
for d in [1, 3, 10]:
    m = poly_logit(d).fit(X_tr, y_tr)
    print(f"  degree {d:>2}: {m[0].n_output_features_:>2} features  train {m.score(X_tr, y_tr):.3f}  test {m.score(X_te, y_te):.3f}")

print("Regularizing degree 10 (C = 1/λ, smaller = stronger regularization)")
for C in [10, 0.3]:
    for pen in ["l2", "l1"]:
        m = poly_logit(10, pen, C=C).fit(X_tr, y_tr)
        w = m[-1].coef_.ravel()
        print(f"  C={C:<4} {pen.upper()}: train {m.score(X_tr, y_tr):.3f}  test {m.score(X_te, y_te):.3f}  "
              f"zeroed coefs {np.sum(np.abs(w) < 1e-8)}/{w.size}")

# Choose regularization strength and degree by cross-validation (hyperparameter search)
grid = GridSearchCV(poly_logit(3, "l2"),
                    {"polynomialfeatures__degree": [1, 3, 5, 10],
                     "logisticregression__C": [0.01, 0.1, 1, 10, 100]},
                    cv=StratifiedKFold(5, shuffle=True, random_state=0))
grid.fit(X_tr, y_tr)
print(f"best combo {grid.best_params_}  CV {grid.best_score_:.3f}  test {grid.score(X_te, y_te):.3f}")

🐟Seen with fish · Tail ratio: one feature beats switching models

With only body length and height, no model can easily get perch vs. roach above 0.8 (test accuracy of the eight models from rule-based to deep learning: 0.26–0.79). Instead of changing the model, let's change the features. "Tail ratio = (length3 − length2) ÷ length2", that is, how long the tail fin is compared with the body length.

How to read it. The tail ratio of perch is 0.026–0.081 and of roach 0.093–0.155, so they do not overlap. The same holds even looking at just the 158 original fish. That is why logistic regression with one added feature reaches 1.000. In contrast, putting in all 6 original features as they are gives 0.917, and the 9 features with 3 more ratios actually dropped slightly to 0.901. Adding the right feature matters more than adding many.

Relation to regularization. Applying L1 regularization (C = 10) to the 9 features gives a cross-validation score of 1.000, and looking at the coefficients, length2 has −73 and length3 has +73. The model built and used "length3 − length2", that is, the tail length, on its own. The default L2 regularization (C = 1) blocks such large coefficients with its penalty and stays at 0.901. Regularization prevents overfitting, but it can also suppress useful signals. If a person creates the tail ratio directly, the same result is achieved without large coefficients, making the model simpler and easier to interpret.

# Chapter 3 · Feature engineering and L1 regularization with fish data: perch vs roach
from sklearn.model_selection import StratifiedGroupKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

d = df[df["species"].isin(["Perch", "Roach"])].copy()
# Create new features (feature engineering): size-independent "body shape" ratios
d["height_ratio"] = d["height_cm"] / d["length2_cm"]           # height ÷ length: how chubby
d["width_ratio"] = d["width_cm"] / d["length2_cm"]             # width ÷ length
d["plumpness"] = np.cbrt(d["weight_g"]) / d["length2_cm"]      # cube root of weight ÷ length: fleshiness
d["tail_ratio"] = (d["length3_cm"] - d["length2_cm"]) / d["length2_cm"]   # tail length ÷ body length
yy, gg = d["species"], d["seed_id"]
cv = StratifiedGroupKFold(5, shuffle=True, random_state=0)
logit = lambda **kw: make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000, **kw))

sets = {"length·height (2)": ["length2_cm", "height_cm"],
        "length·height + body ratio": ["length2_cm", "height_cm", "height_ratio"],
        "length·height + tail ratio": ["length2_cm", "height_cm", "tail_ratio"],
        "original 6 features": FEATS,
        "6 + 3 ratios (9)": FEATS + ["height_ratio", "width_ratio", "plumpness"]}
print(f"baseline (answer perch for all): {(yy == 'Perch').mean():.3f}")
for name, cols in sets.items():
    s = cross_val_score(logit(), d[cols], yy, cv=cv, groups=gg)
    print(f"{name:<22} {s.mean():.3f} ± {s.std():.3f}")

cols = sets["6 + 3 ratios (9)"]
print("\nCoefficients by L1 regularization strength (smaller C = stronger regularization)")
for C in [10, 1, 0.1]:
    m = logit(penalty="l1", C=C, solver="liblinear").fit(d[cols], yy)
    w = m[-1].coef_.ravel()
    kept = [f"{c}:{v:+.2f}" for c, v in zip(cols, w) if abs(v) > 1e-6]
    acc = cross_val_score(logit(penalty="l1", C=C, solver="liblinear"), d[cols], yy, cv=cv, groups=gg).mean()
    print(f"C={C:<4} features kept {len(kept)}/9  CV {acc:.3f}  {', '.join(kept)}")

Combining multiple algorithmsVoting · Bagging · Random forest · Boosting

Combine the judgments of several models to reduce wobble and skew.

①What's the problem?

A single model may have errors skewed to one side (bias, a different meaning from the bias term b in w·x + b), or its judgment may swing widely when the data changes only slightly (variance). Combining the judgments of several models can reduce these weaknesses.

0.842 ± 0.035A single decision tree with unlimited depth (5-fold cross-validation)
0.878 ± 0.014Random forest of 100 trees: the score rises and the wobble shrinks
0.887 ± 0.011KNN alone: on this data, similar to the ensembles. Ensembles don't always win

In plain termsVoting is a vote among experts with different specialties; bagging is a majority vote among students who studied the same subject with different sets of practice exams; random forest additionally has those students study only a random part of the subject each, so they are less alike; and boosting is a wrong-answer-notebook relay where the next person focuses on the problems the previous person got wrong.

②Sorting it into three branches
Soft voting: p̂(y | x) = (1/M) Σm pm(y | x)Average the probabilities of M models. Hard voting is a majority vote over predicted classes.
Bagging: f̂(x) = (1/M) Σm fm(x),   fm is trained on bootstrap sample mTraining the same model many times on different samples and averaging cancels out the part that wobbles with the sample (variance).
Boosting: FM(x) = Σm αm hm(x),   αm = ½ ln((1 − errm) / errm)AdaBoost. The lower a model's error rate errm, the bigger its say αm; the weights of misclassified points grow by a factor of eαm so the next model focuses on them.
③Try it · Voting

Test accuracy is computed on this page. Voting beats the weakest model, but as in this example, it doesn't always beat the best single model. When a weak model is mixed in, it drags the average down.

# 4. Combining multiple algorithms: voting, bagging, random forest, boosting
import warnings; warnings.filterwarnings("ignore")
from sklearn.datasets import make_moons
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import (VotingClassifier, BaggingClassifier,
                              RandomForestClassifier, GradientBoostingClassifier)

X, y = make_moons(n_samples=600, noise=0.35, random_state=2)
cv = StratifiedKFold(5, shuffle=True, random_state=0)

logit = make_pipeline(StandardScaler(), LogisticRegression())
knn   = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=15))
tree  = DecisionTreeClassifier(random_state=0)                 # no depth limit: prone to overfitting

models = {
    "Logistic regression (alone)":logit,
    "KNN (alone)":               knn,
    "Decision tree (alone)":     tree,
    "Voting (3 above, soft)":    VotingClassifier([("lr", logit), ("knn", knn),
                               ("tree", DecisionTreeClassifier(max_depth=5, random_state=0))], voting="soft"),
    "Bagging (100 trees)":       BaggingClassifier(DecisionTreeClassifier(), n_estimators=100, random_state=0),
    "Random forest (100 trees)": RandomForestClassifier(n_estimators=100, random_state=0),
    "Gradient boosting (100 stages)": GradientBoostingClassifier(n_estimators=100, max_depth=2, random_state=0),
}
for name, m in models.items():
    s = cross_val_score(m, X, y, cv=cv)
    print(f"{name:<22} {s.mean():.3f} ± {s.std():.3f}")

Summary on one pageChecklist

Check these in order and you won't miss most opportunities for improvement.

★Check in order
  1. Measure the baseline · Write down the stratified cross-validation scores of answering the majority class and of a basic logistic regression.
  2. Fix the evaluation first · Use stratify and stratified K-fold cross-validation, keep preprocessing inside a Pipeline, and if the data is imbalanced, look at recall and F1 too.
  3. Check the training process · See whether the loss curve decreases smoothly, and tune the learning rate, batch size and early stopping.
  4. Engineer features and regularize · Add features while watching the gap between training and test scores, and choose λ (or C) by grid search.
  5. If that's still not enough, combine models · Try a random forest or gradient boosting, or voting among models of different kinds.
  6. Use the test set only once, at the very end · Look at it just once after every choice has been made, and report that score.
★Three key takeaways
1. If you can't trust the score, every improvement is an illusion. Stratified cross-validation and checking for leakage are the first step.
2. Adding features makes the boundary more flexible, but overfitting follows. Regularization (L2, L1) and cross-validation find the balance point in between.
3. Training is finding the lowest spot in the loss landscape, and an ensemble combines the judgments of several models to reduce bias and variance.

Evaluation design

Baseline

AnalogyYour "current record," measured before you start training for a race. You need it to know whether you've improved.

MeaningThe score measured first with the simplest method (e.g. always answering the majority class, or a basic logistic regression).

Training, validation and test sets

AnalogyThe textbook (training), mock exams (validation) and the college entrance exam (test). You must never peek at the entrance exam questions while studying.

MeaningData for learning the weights, data for choosing settings, and data for measuring performance only once at the very end.

Stratified sampling

AnalogyDrawing a sample for an opinion poll so that its age-group proportions match those of the actual population exactly.

MeaningA way of splitting so that each piece keeps the same class proportions as the whole.

Cross-validation

AnalogyTaking several practice exams with different question sheets and averaging the scores, so you are not fooled by one lucky score.

MeaningA method that splits the data into K pieces, takes turns using one piece for testing, and averages the scores.

Data leakage

AnalogySneaking a look at the answer sheet before the exam. The score is high, but it isn't real skill.

MeaningA mistake where information from the test data slips into the training process and inflates the score.

Class imbalance

AnalogyA test for a disease only 1 in 100 people has. Just answering "everyone is negative" scores 99 points.

MeaningA state where the number of data points differs greatly between classes. Accuracy hides the real skill.

Confusion matrix

AnalogyAn error-analysis sheet that breaks down a report card's "right/wrong answers" by question type.

MeaningA table that lays out actual classes and predicted classes as rows and columns and counts each combination.

Precision

AnalogyThe probability that there is really a fire when the fire alarm goes off. Many false alarms lower it.

MeaningThe proportion of actual positives among those predicted positive. TP / (TP + FP).

Recall

AnalogyThe proportion of actual fires for which the alarm went off. Many missed fires lower it.

MeaningThe proportion of actual positives that the model found. TP / (TP + FN).

F1 score

AnalogyA balanced score across two subjects, precision and recall. Doing well in only one subject gives a low score.

MeaningThe harmonic mean of precision and recall. 2PR / (P + R).

Training process

Loss

AnalogyHow far a dart missed the bullseye. The farther, the worse.

MeaningA single number measuring how different the prediction is from the correct answer. Training is the process of reducing this value.

Gradient descent

AnalogyFinding the valley on a mountain in thick fog by feeling only the slope under your feet and stepping downhill one step at a time.

MeaningA method that moves the weights little by little in the direction that reduces the loss (opposite the gradient).

Learning rate

AnalogyYour stride when walking down the mountain. Too big and you leap over the valley; too small and you won't get down before sunset.

MeaningThe value that sets how far the weights move in one step. Its symbol is η (eta).

Epoch

AnalogyWorking through a whole workbook once, from beginning to end.

MeaningThe unit of going through the entire training data once.

Batch

AnalogyHow many people to ask when asking for directions. Asking all 40 is accurate but slow; asking one is fast but may be wrong.

MeaningThe bundle of data used for one weight update. Its size is written B.

Stochastic gradient descent

AnalogyAsking just one passerby for directions and immediately taking a step. You move often, but you zigzag.

MeaningGradient descent that updates the weights every time with a batch size of 1 (more broadly, small batches).

Momentum

AnalogyThe inertia of a ball rolling downhill. Once it picks up speed, small bumps don't easily stop it.

MeaningAn add-on to gradient descent that carries over part of the previous step's direction. It reduces wobbling and speeds up convergence.

Adam

AnalogyA hiker who adjusts their stride on every path. Careful steps in rough directions, long strides in flat ones.

MeaningA variant of gradient descent that automatically adjusts the learning rate for each weight and also uses momentum. It is the default optimization method for neural networks.

Early stopping

AnalogyStopping memorizing and heading to the exam hall once your mock exam scores stop going up.

MeaningA method that stops training when the validation score hasn't improved for several epochs.

Local minimum / maximum

AnalogyThe bottom of the lowest valley around, the top of the highest peak around.

MeaningA point whose value is the smallest (largest) compared with its surroundings. The gradient there is 0.

Local minimum

AnalogyA small puddle halfway up a mountain. If you get stuck in it on the way down, you never find the truly lowest valley.

MeaningA point that is the lowest in its neighborhood but not the lowest overall.

Saddle point

AnalogyThe middle of a horse saddle. Front to back it is a peak; side to side it is a bottom.

MeaningA point where the gradient is 0 but which is neither a minimum nor a maximum.

Features and regularization

Feature engineering

AnalogyPrepping ingredients before cooking. Just as julienning a whole potato makes stir-frying possible, you reshape the data so the model can use it well.

MeaningCreating new variables (squares, products, ratios, etc.) from existing ones and feeding them to the model.

Overfitting

AnalogyA student who memorized the answers to past exam questions wholesale. Perfect on past questions, but stuck on new ones.

MeaningA state where the model fits the training data well but performs worse on new data.

Underfitting

AnalogyA student who only skimmed the textbook. Can't solve past questions or new ones.

MeaningA state where the model is too simple to fit even the training data well.

Regularization

AnalogyA luggage weight limit. If heavier bags cost extra fees (penalties), you pack only what you really need.

MeaningA method that adds a penalty to the loss as the weights grow, making the model simpler.

L2 regularization (ridge)

AnalogyMaking every item of luggage a little lighter. Nothing gets thrown out.

MeaningA λ Σ w² penalty. It shrinks the coefficients evenly but does not make them 0.

L1 regularization (lasso)

AnalogyLeaving unnecessary items out entirely. Fewer things remain in the bag.

MeaningA λ Σ |w| penalty. It makes some coefficients exactly 0, which has the effect of selecting features.

Hyperparameter

AnalogyThe heat level and cooking time a chef sets in advance.

MeaningSettings a person chooses before training. Degree, λ (or C), learning rate, tree depth, etc.

Grid search

AnalogyCooking all 3 heat levels × 4 cooking times = 12 combinations and choosing the one with the best taste rating (cross-validation).

MeaningA method that compares every combination of candidate hyperparameters with cross-validation and picks the best.

Combining multiple models

Ensemble

AnalogyAn orchestra. Many instruments playing together sound richer than one, and mistakes get drowned out.

MeaningA method that combines the predictions of several models into one prediction.

Bias and variance

AnalogyShooting at a target. Bias is arrows clustering off to one side; variance is arrows scattering in all directions.

MeaningTwo sources of model error. Simple models tend to have high bias, complex models high variance. ※ This is different from the "bias (bias term)" that names b in the formula w·x + b. Here it means "how far predictions lean to one side."

Voting

AnalogyA vote by an expert panel. It gathers opinions from different specialties.

MeaningA method that combines the predictions of different models by majority vote (hard) or by averaging probabilities (soft).

Bootstrap

AnalogyDrawing a ball from a bag, recording it and putting it back, n times. The same ball may come out twice.

MeaningA method that redraws a sample of the same size from the original data, allowing duplicates.

Bagging

AnalogyA majority vote among students who studied the same subject with different sets of mock exams.

MeaningA method that trains the same kind of model on each bootstrap sample and averages them (majority vote). It reduces variance.

Random forest

AnalogyMaking those students each study only a random part of the subject too, so they resemble each other less.

MeaningA decision tree ensemble that adds "look at only a random subset of features at each split" to bagging.

Boosting

AnalogyA wrong-answer-notebook relay. The next person focuses on studying the questions the previous person got wrong.

MeaningA method that adds models one after another, giving more weight to the data the previous model got wrong. It reduces bias.
